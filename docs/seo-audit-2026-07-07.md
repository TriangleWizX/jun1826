# Sensei Sandy Full-Site SEO Audit

Date: 2026-07-07  
Site: https://senseisandy.com  
Repo: `/home/twizss/Documents/ssbjjweb/tmb`

## Scope And Caveats

This audit used the repo's existing SEO, sitemap, link, redirect, schema, and metadata QA scripts plus targeted live checks. The worktree was already heavily dirty before this audit, including `.htaccess`, `config/legacy-redirects.json`, generated pages, crawl reports, scripts, and `package.json`, so remediation should review current user-owned changes before applying fixes.

Known intentional behavior preserved:

- `/store` live check returns `301 https://senseisandy.com/bjj-gear-store-tannersville-ny`.
- `/thanks` returns `200` and includes `<meta content="noindex, nofollow" name="robots"/>`; this should remain excluded from indexing.

## Executive Summary

No confirmed critical index-blocking defect was found. The main SEO risk is production drift: live sitemaps and live page metadata do not match the cleaner local repo state. Local static SEO checks pass for 258 sitemap URLs, but live sitemap files expose 308 URLs and include 33 redirecting URLs that are absent from local sitemap files. Several live metadata failures also appear to be stale deploy output, because local files already have the expected no-slash canonicals and Open Graph tags.

Priority order:

1. Fix production sitemap and metadata drift.
2. Resolve the local `.htaccess` managed redirect block sync failure.
3. Repair the broad blog linkout-rule regression.
4. Clean the two static blog trailing-slash canonical link issues.
5. Improve or replace the unreliable `qa:links:live` run path before relying on its CSV output.

Affected surface:

- Live `/bjj-classes/adults-tannersville-ny`
- Live `/bjj-classes/cairo-ny`
- Live `/bjj-classes/catskill-ny`
- Live `/bjj-classes/haines-falls-ny`

Fix:

1. Deploy the current local versions of the affected files.
2. Confirm the deployment process is publishing generated `/bjj-classes/*` pages and top-level HTML files from the same repo state as the sitemaps.

### 6. `http://www` Canonical Host Normalization Takes Two Hops

Issue: `http://www.senseisandy.com/` normalizes to apex HTTPS through two redirects instead of one.

Evidence:

- `bash scripts/qa-canonical-host-live.sh`:
  - Pass: `http://senseisandy.com/ -> https://senseisandy.com/` in 1 redirect
  - Fail: `http://www.senseisandy.com/` used 2 redirects
- Direct chain: `http://www.senseisandy.com/ -> https://www.senseisandy.com/ -> https://senseisandy.com/`.

Affected surface:

- Server-level canonical host redirect rules.
- `.htaccess` or hosting control panel redirect settings.

Fix: Add or adjust the host rule so `http://www.senseisandy.com/*` redirects directly to `https://senseisandy.com/*`.

Validation:

- `bash scripts/qa-canonical-host-live.sh`
- `curl -sSI -L --max-redirs 5 http://www.senseisandy.com/`

### 7. Live Link QA Is Currently Inconclusive

Evidence:

- `npm run qa:links:live` failed with `fetch failed` in sandbox.

- Retried with `--concurrency 1 --timeout-ms 30000` and `--base-url https://senseisandy.com`; still failed.
- A direct Node fetch of `https://senseisandy.com/` returned `200`.
- `crawl-reports/internal-links-4xx-5xx.csv` currently contains 313 data rows with status `0`, which should not be treated as confirmed 4xx/5xx evidence.

Affected surface:

- `scripts/qa-links-live.mjs`
- `crawl-reports/full-crawl-internal-links.csv`
- `crawl-reports/internal-links-4xx-5xx.csv`
